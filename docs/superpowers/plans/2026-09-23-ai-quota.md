# Pilar 3: Quotas de Uso de IA — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Impor um limite diário de 50 chamadas às rotas de IA por assinante ativo (`enhance`, `autofill`, `analyze-references`, `parse-product-url`), e migrar o circuit breaker de alta demanda do Gemini de estado em memória para o mesmo Postgres compartilhado.

**Architecture:** Novo módulo `api/_lib/quota/` com dois sub-domínios paralelos — contagem de uso diário e circuit breaker — cada um com: tipos, lógica pura testável, repo em memória (testes) e repo Supabase (produção). Um wrapper fino `requireQuota` (mirror de `requireSubscription`) é chamado nas 4 rotas de IA logo após `requireActiveSubscription`. `gemini.ts` troca a variável em memória pelo repo do circuit breaker via injeção de dependência com default, sem mudar a assinatura pública chamada pelas rotas.

**Tech Stack:** TypeScript, Vitest, Supabase Postgres (via `supabaseAdmin`, service role), `Intl.DateTimeFormat` nativo do Node (sem dependência nova de timezone).

**Spec:** `docs/superpowers/specs/2026-09-23-ai-quota-design.md`

## Global Constraints

- Limite: **50 chamadas/dia**, cota única compartilhada entre as 4 rotas de IA (spec, seção "Enforcement").
- Timezone do reset: `America/Sao_Paulo` — nunca UTC nem a data do cliente (spec, "Modelo de dados").
- Contagem incrementa **depois** de `requireActiveSubscription` e **antes** da chamada ao Gemini; toda tentativa que passa da assinatura consome cota, mesmo em fallback local (spec, "Contador de uso").
- Ao estourar: bloquear com HTTP 429, nunca degradar modelo (spec, "Não-objetivos").
- Sem fila assíncrona, sem tiers por plano, sem cota por rota individual (spec, "Não-objetivos").
- Import relativo dentro de `api/` sempre com extensão `.js` (ESM + `type:module` na Vercel — sem isso toda function quebra em produção).
- Nenhuma mudança de frontend é necessária (spec, seção "Frontend", revisada em 2026-09-23) — as 4 telas já exibem `error` de qualquer resposta não-ok.

## Review Focus

- **Race condition no incremento de cota.** Duas chamadas simultâneas do mesmo usuário não podem resultar em contagem perdida (uma sobrescrevendo a outra). Mitigado com uma função Postgres (`increment_ai_usage`) que faz `INSERT ... ON CONFLICT ... DO UPDATE SET count = count + 1` atomicamente no banco — nunca um "ler depois escrever" em JS. Testado na Task 3 com duas chamadas "simultâneas" ao repo em memória.
- **Cálculo de dia local errado perto da virada de meia-noite.** Se `todaySaoPauloDateString`/`nextMidnightSaoPaulo` usarem UTC em vez do offset de São Paulo, o reset acontece na hora errada (early ou late por até 3h). Testado na Task 2 com instantes específicos dos dois lados de 00:00 SP.
- **Falha do circuit breaker derruba a geração de IA.** Como o circuit breaker é só uma otimização de resiliência, uma falha ao ler/escrever seu estado no Postgres nunca deve impedir a chamada real ao Gemini. Coberto na Task 5/6: leitura e escrita do circuit breaker envoltas em `try/catch`, com fallback silencioso pra ordem padrão de modelos.
- **Cota contabilizada antes da checagem de assinatura ativa**, o que deixaria um usuário sem assinatura consumir/poluir a tabela de cota. Mitigado pela ordem de chamadas fixada nas 4 rotas: `authenticate` → `requireActiveSubscription` → `requireQuota` (nunca a ordem inversa) — verificado na Task 4 ao revisar cada arquivo modificado.
- **Nova tabela `ai_usage_daily` sem RLS de escrita liberando update direto do cliente**, permitindo um usuário zerar a própria cota. Mitigado: nenhuma policy de insert/update é criada para o client role; só a função `increment_ai_usage` (marcada `security definer`, executável só por `service_role`) escreve. Verificado na Task 1 ao aplicar a migração e conferir as policies.

create table public.ai_usage_daily (
  user_id uuid not null references auth.users(id) on delete cascade,
  usage_date date not null,
  count integer not null default 0,
  primary key (user_id, usage_date)
);

alter table public.ai_usage_daily enable row level security;

create policy "ai_usage_select_own" on public.ai_usage_daily
  for select using (auth.uid() = user_id);

-- Incremento atômico: nunca "ler depois escrever" em código da aplicação.
create or replace function public.increment_ai_usage(p_user_id uuid, p_date date)
returns integer
language sql
security definer
set search_path = public
as $$
  insert into public.ai_usage_daily (user_id, usage_date, count)
  values (p_user_id, p_date, 1)
  on conflict (user_id, usage_date)
  do update set count = ai_usage_daily.count + 1
  returning count;
$$;

revoke all on function public.increment_ai_usage(uuid, date) from public;
grant execute on function public.increment_ai_usage(uuid, date) to service_role;

create table public.gemini_circuit_breaker (
  id boolean primary key default true,
  last_high_demand_at timestamptz,
  constraint gemini_circuit_breaker_single_row check (id)
);

insert into public.gemini_circuit_breaker (id, last_high_demand_at)
values (true, null);

alter table public.gemini_circuit_breaker enable row level security;
-- Sem policies: só o service role acessa (nenhum policy = nenhum acesso pro client role).
```

const TIME_ZONE = 'America/Sao_Paulo';

// Offset (em ms) da timezone em relação a UTC no instante `date`. Não assume um
// offset fixo (-3h): funciona mesmo se o Brasil reintroduzir horário de verão.
function timeZoneOffsetMs(date: Date, timeZone: string): number {
  const parts = new Intl.DateTimeFormat('en-US', {
    timeZone,
    hour12: false,
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
    hour: '2-digit',
    minute: '2-digit',
    second: '2-digit',
  })
    .formatToParts(date)
    .reduce<Record<string, string>>((acc, p) => {
      acc[p.type] = p.value;
      return acc;
    }, {});

  const asIfUTC = Date.UTC(
    Number(parts.year),
    Number(parts.month) - 1,
    Number(parts.day),
    Number(parts.hour === '24' ? '0' : parts.hour),
    Number(parts.minute),
    Number(parts.second)
  );
  return asIfUTC - date.getTime();
}

export function todaySaoPauloDateString(now: Date): string {
  return new Intl.DateTimeFormat('en-CA', { timeZone: TIME_ZONE }).format(now);
}

export function nextMidnightSaoPaulo(now: Date): Date {
  const [year, month, day] = todaySaoPauloDateString(now).split('-').map(Number);
  const tomorrowAsIfUTC = new Date(Date.UTC(year, month - 1, day + 1, 0, 0, 0));
  const offsetMs = timeZoneOffsetMs(tomorrowAsIfUTC, TIME_ZONE);
  return new Date(tomorrowAsIfUTC.getTime() - offsetMs);
}
```

export interface MemoryUsageRepo extends UsageRepo {
  counts: Map<string, number>;
}

// `seed` usa a chave `"${userId}|${dateStr}"`.
export function createMemoryUsageRepo(seed: Record<string, number> = {}): MemoryUsageRepo {
  const counts = new Map<string, number>(Object.entries(seed));

  return {
    counts,
    async incrementAndGetUsage(userId, dateStr) {
      const key = `${userId}|${dateStr}`;
      const next = (counts.get(key) ?? 0) + 1;
      counts.set(key, next);
      return next;
    },
  };
}

```ts
import type { VercelResponse } from '@vercel/node';
import type { AuthenticatedUser } from '../auth.js';
import { decideQuota } from '../quota/decideQuota.js';
import { createSupabaseUsageRepo } from '../quota/usageRepo.js';
import { nextMidnightSaoPaulo } from '../quota/timezone.js';

// Chamar logo após `requireActiveSubscription`: `if (!(await requireQuota(user, res))) return;`
export async function requireQuota(user: AuthenticatedUser, res: VercelResponse): Promise<boolean> {
  const now = new Date();
  const decision = await decideQuota(createSupabaseUsageRepo(), user.id, now);
  if (decision === 'ok') return true;
  if (decision === 'exceeded') {
    res.status(429).json({
      error: 'Limite diário de gerações atingido. Volta à meia-noite.',
      code: 'quota_exceeded',
      resetAt: nextMidnightSaoPaulo(now).toISOString(),
    });
  } else {
    res.status(503).json({ error: 'Não foi possível verificar sua cota de uso. Tente novamente.' });
  }
  return false;
}
```

// Lógica pura: dado quando foi a última alta demanda e o instante atual,

export function pickModelOrder(lastHighDemandAt: string | null, now: Date): string[] {
  const last = lastHighDemandAt ? new Date(lastHighDemandAt).getTime() : 0;
  if (now.getTime() - last < HIGH_DEMAND_WINDOW_MS) {
